01 / THE PROBLEM · A SIMPLE EXAMPLE

The tests passed. The code still broke.

An AI was asked to make average() shorter. Every test stayed green - because no test ever tried an empty list.

A simple made-up example to explain the idea. Slides 8 and 9 show real results from this project.12 s

02 / THE IDEA

Don't take the AI's word. Make it show proof.

Same change, two reviews. One gives an opinion. The other runs a test that anyone can repeat.

A normal AI review

“I reviewed the change to average(). The code is shorter and all tests pass. ✓ Approve.”
What it missed: it never tried an empty list - so it never saw the crash.
Sounds sure. Shows nothing you can check.

Our review

  1. 1
    Write down the promiseaverage() must never crash - even for an empty list.
  2. 2
    Actually run itaverage([])
  3. 3
    See what happenedZeroDivisionError → BROKEN, with the proof attached.
Anyone can run that one line and see the same crash.
An opinion can be wrong without anyone noticing. A test shows you.15 s

03 / STEP 1 · GATHER EVIDENCE

Step 1: gather the evidence.

What was promised, what the AI changed, and why it did it - from the AI's own chat log. Then we put them side by side.

The map can be stored in MongoDB Atlas. No chat log saved? That card says “unknown” instead of guessing.12 s

04 / STEP 2 · MAKE IT CHECKABLE

Step 2: turn the promise into a test.

“Never crashes” is vague. We rewrite it so a computer can check it: for every list - including the empty one - average() must not crash.

Every claim keeps a link to where it came from - that is the audit trail.11 s

05 / STEP 3 · RUN IT, THEN LOOK AROUND

Step 3: run it, then look around.

We try every list, including the empty one. It crashes - and one crash is enough to prove the claim wrong. Then we check what else uses average().

A lead is not a verdict - nothing is called broken until its own check fails.13 s

06 / STEP 4 · ANSWER HONESTLY

Step 4: only four honest answers.

An answer only counts if a real run produced it. The AI can suggest ideas, but it can't hand out answers.

No “looks good to me” - those four words are the whole vocabulary.11 s

07 / HOW IT GROWS

We check promises, not lines.

One promise covers many lines. Each review only reads what changed - and every promise already checked becomes a test for the next change.

Today each review lists the earlier promises it re-checks; an automatic shared registry is the next step.13 s
