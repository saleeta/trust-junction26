2 · records become nodes

one node per fact, with its provenance: PROMPT TOOL_CALL FILE COMMIT (the toy's graph really has 32 nodes and 37 edges)

3 · edges connect them

caused prompt→call · writes call→file · inspects call→commit

4 · fused with real git history

parent_of commit→base commit, so the graph answers “what was this change built on?” from git, not from memory

        three depths, one checker discipline

        R-RUN - A claim is only true or false because code was executed.

        R-HIST - A promise made by an earlier PR is a test for every later PR.

        R-CALL - If a function's promise is refuted, every function that calls it is re-checked on the same counterexample.

        R-TEST - A passing test only speaks for the inputs it actually runs.

        R-HUMAN - Questions of intent are not decidable by code. They go to a person.

        What the colors mean

        blue - the lookup path

        The question enters the graph at one node; only the path from the root to that node is opened. Everything else stays unread.

        red - falsification propagation

        When a claim is falsified, the walk re-enters the graph and visits everything that claim was load-bearing for - its blast radius.

        purple - revisited

        A node already seen by an earlier pass and touched again - the “recurring traversal” signal, counted per pass.

        token chip on every node

        Each node costs what its text costs. The walk's total is the sum of what was actually opened - not the whole graph.
