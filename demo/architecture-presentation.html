01 / THE PROBLEM

AI ships the patch. The tests stay green. The promise is broken.

Green tests only prove what someone thought to test - not what the code promised.

This failure is the everyday AI-coding accident: a contract changed, callers and docs not told.14 s

02 / THE IDEA

Don't trust the AI's opinion. Check its claims.

A claim is a sentence + a source + a scope + one command that re-runs the check. Verdicts come only from executed code.

03 / STEP 1 · GATHER EVIDENCE

Three sources feed one review graph.

Requirements say what was promised. Git says what changed. Entire says what the author was thinking - when it exists.

Original author session: unavailable - the gap is labelled, never papered over.14 s

04 / STEP 2 · SAY IT FORMALLY

A promise becomes a claim you can check.

"Never crashes" becomes: for every product, the lookup does not raise. One sentence, one scope, one command.

Every claim carries its source and check - that is the audit trail.17 s

05 / STEP 3 · CHECK, THEN FOLLOW THE BLAST RADIUS

One failed claim opens its footprint.

Run the check. A counterexample refutes the claim. Then ask: where else does this assumption matter?

Impact paths are leads until checked - one refutation is reused, not re-invented.18 s

06 / STEP 4 · LABEL HONESTLY

Four verdicts. Only executed code may set them.

A verdict without a witness is an opinion. A verdict with one is evidence.

These four words are the trust contract - vague praise is not in the vocabulary.12 s
