01 / THE PROBLEM

The tests passed. The app still broke.

An AI rewrote one line of a shop app. Every test stayed green - because no test ever asked for a product the shop doesn't sell.

The everyday AI-coding accident: the code changes, but nobody re-checks what it promised.14 s

02 / THE IDEA

Don't trust the AI. Check it.

Instead of “looks fine to me”, every claim comes with a test anyone can run again. Only a real run decides the answer.

Normal AI review

“Looks safe to me.”

?
An opinion. No proof. Nothing to re-run.

Our review

A claim, a check you can run, and what it found.

Proof you can repeat in seconds.
The AI may suggest claims. Only running the code may answer them.15 s

03 / STEP 1 · GATHER EVIDENCE

Step 1: gather the evidence.

What was promised, what the AI changed, and - if it was saved - the AI's own chat log. All three go into one review map.

No chat log was saved for this patch - so we say “unknown” instead of guessing.14 s

04 / STEP 2 · MAKE IT CHECKABLE

Step 2: turn the promise into a test.

“Never crash” is vague. We rewrite it so a computer can check it: for every product - even fake ones - getting the price must not crash.

Every claim keeps a link to where it came from - that is the audit trail.17 s

05 / STEP 3 · RUN IT, THEN LOOK AROUND

Step 3: run it, then look around.

We try every product, including a fake one. It crashes - and one crash is enough to prove the claim wrong. Then we check what else uses that code.

A lead is not a verdict - nothing is called broken until its own check fails.18 s

06 / STEP 4 · ANSWER HONESTLY

Step 4: only four honest answers.

An answer only counts if a real run produced it. The AI can suggest ideas, but it can't hand out answers.

No “looks good to me” - those four words are the whole vocabulary.12 s
